# Segments, banks and cartridges

Normally the assembler creates a **program** that is loaded from a disk or a cassette. A **cartridge** is different: it is a plug-in module with read-only memory (ROM). The computer sees its content in the address space at once, and the program starts when you switch on. The three directives on this page describe where bytes end up in the cartridge: `.segment` names and checks ranges, `.bank` chooses a memory bank, and `.cartridge` turns everything into a cartridge image.

This page belongs to the [assembler manual](help:assembler). Lines of the form `;= 01 02` in the examples show the generated bytes. All examples are checked with the assembler.

## Segments: `.segment`

A **segment** is a contiguous block of generated bytes. Every `.org` starts a new one. With `.segment` you give the following segments a name (it appears in the memory map, in the build log and in the debug info) and you can set the **allowed address range**.

```
.segment "NAME"                 ; name only
.segment "NAME", from, to       ; name and check the range
.segment                        ; remove name and range
```

If a byte leaves the range `from`-`to` (both limits are included), the assembler reports **E301**. This way you catch errors early, such as "code runs into the data":

```asm
.segment "CODE", $c000, $c0ff
*= $c000
        nop
.segment "DATA", $c100, $c1ff
*= $c100
        .byte 1
;=* ea
```

```asm fehler
.segment "CODE", $c000, $c003
*= $c000
        .fill 8, 0
```

```text
error[E301]: segment 'CODE' leaves its range $C000-$C003 ($C000..$C007)
```

If two segments overlap (even without names), the assembler reports **E301** ("segments overlap").

## Banks: `.bank`

Cartridges are often larger than the address space that the computer provides for them (8 KB at `$8000`). The rest is in more **banks**. At run time, the program switches a bank on, and its content appears at the same address.

```
.bank n            ; n = 0 to 1023
```

- Each bank has its **own address space and program counter**. After `.bank 1`, you set the address inside this bank with `.org`. If you switch back later, it continues where bank 0 stopped.
- Bank 0 is the default.
- Banks exist only in the cartridge formats (`crt`, `car`, `rom`). For a normal program (`prg`, `xex`), the build reports "multiple banks (.bank) exist only in the cartridge formats crt/car/rom".

## Cartridges: `.cartridge`

```
.cartridge "type", "NAME"
```

The type sets the format. `NAME` is the cartridge name (up to 32 characters, uppercase; default `VINTAGECODER`). If `.cartridge` is in the source, the build automatically creates a cartridge instead of a program (`.crt` on the C64, `.car` on the Atari). On the command line, `--cart type` forces the type and `--format crt|car|rom` forces the format. The assembler fills unused areas with `$FF`.

| System | Types | Output |
|---|---|---|
| C64 `.crt` | `normal` (also `8k`, `16k`), `ocean`, `magicdesk`, `easyflash`, `actionreplay` (also `ar`), `ultimax` | `.crt` (VICE cartridge format) |
| Atari `.car` / `.rom` | `8k`, `16k`, `xegs` | `.car` with header or `.rom` raw |
| VIC-20 | `a0`, `20`, `40`, `60` | raw 8 KB image, extension = type |

An unknown type gives a message only when the cartridge is created, for example "unknown cartridge type 'gibts' (normal, 16k, ocean, magicdesk, easyflash, actionreplay, ultimax)".

### C64 cartridges

The C64 maps a cartridge in at `$8000` (and for some types at `$A000`). When you switch on, the computer checks whether the signature **CBM80** is at `$8004` (`$C3 $C2 $CD $38 $30`). Before it are two words: the cold start vector and the warm start vector, that is, the addresses where the program begins. If the signature is missing, the cartridge does not start.

```asm fmt=crt
.cartridge "normal", "MY CARTRIDGE"
*= $8000
        .word kalt, kalt
        .byte $c3, $c2, $cd, $38, $30      ; CBM80
kalt:   inc $d020
        jmp kalt
```

(The library `lib/cart.inc` of the examples contains the macro `cbm80_header kalt, warm`, which creates these nine bytes; see `examples/c64/cart_demo`.)

| Type | Structure |
|---|---|
| `normal` / `8k` | bank 0 only, code in `$8000`-`$BFFF`. If a byte is at `$A000` or higher (or `16k` is set), a 16 KB cartridge is created, otherwise an 8 KB cartridge |
| `ocean` | 16 to 64 banks of 8 KB (the number is rounded up to a power of two). Banks 0-15 are at `$8000`-`$9FFF`, banks from 16 on are at `$A000`-`$BFFF` |
| `magicdesk` | 4 to 16 banks of 8 KB at `$8000`-`$9FFF` |
| `easyflash` | up to 64 banks; each bank has ROML at `$8000`-`$9FFF` and ROMH at `$A000`-`$BFFF` **or** `$E000`-`$FFFF` (not both). Bank 0 needs ROMH code with the start vectors at `$FFFC` |
| `actionreplay` | exactly four banks of 8 KB at `$8000`-`$9FFF` |
| `ultimax` | bank 0 only: ROML `$8000`-`$9FFF` (optional) and ROMH `$E000`-`$FFFF` with the reset vector at `$FFFC` |

Bank switching at run time (from `lib/cart.inc`): for Ocean `lda #$80 | n` / `sta $de00`, for Magic Desk `lda #n` / `sta $de00`. The code that switches must be at the same place in every bank or run in RAM. [`.relocate`](help:asm-directives) is often used for this:

```asm fmt=crt
.cartridge "magicdesk", "BANKS"
.segment "BANK0", $8000, $9fff
.bank 0
*= $8000
        .word start, start
        .byte $c3, $c2, $cd, $38, $30
start:  ldx #0
copy:   lda image,x             ; copy the switching code to RAM
        sta $c000,x
        inx
        cpx #image_end - image
        bne copy
        jsr $c000
        jmp *
image:
        .relocate $c000        ; runs in RAM at $C000
        lda #1                  ; switch bank 1 on
        sta $de00
        lda $8100               ; read the marker there
        sta $0400
        lda #0                  ; back to bank 0
        sta $de00
        rts
        .endrelocate
image_end:
.segment "BANK1", $8000, $9fff
.bank 1
*= $8100
        .byte $b1               ; marker of bank 1
```

### Atari cartridges

An Atari cartridge is at `$A000`-`$BFFF` (8 KB) or `$8000`-`$BFFF` (16 KB). The assembler adds the start vectors at `$BFFA`-`$BFFF` (start address, flag, option, initialization routine) itself if your program does not create them: the start address comes from `.run`, the option is "start cartridge", and the initialization is a single `rts`. If `.run` is missing, the build reports "Atari cartridge: start address missing (.run or own vectors at $BFFA)".

```asm fmt=car target=atari8
.cartridge "8k"
*= $a000
start:  jmp start
.run start
```

- `8k` / `16k` / no value: the size comes from the code (if something is below `$A000`, it becomes a 16 KB cartridge).
- `xegs`: bank cartridge, 32, 64 or 128 KB (4, 8 or 16 banks of 8 KB). Banks 0 to n-2 appear at `$8000`-`$9FFF`, and the **last bank** is fixed at `$A000`-`$BFFF`. You switch with a write access to `$D500`.
- `.rom` is the same image without the 16-byte header of the `.car` file.

### VIC-20 cartridges

Raw 8 KB images for one memory block: `a0` (`$A000`-`$BFFF`), `20`, `40` or `60` (`$2000`, `$4000`, `$6000`). There are no banks. The system starts a cartridge at `$A000` by itself if the signature `A0CBM` is at `$A004` (`$41 $30 $C3 $C2 $CD`) and the cold and warm start addresses are before it. More under [VIC-20](help:vic20).

## Typical errors

| Message | Cause |
|---|---|
| **E301** segment leaves its range / segments overlap | code too long for the range; two `.org` at overlapping addresses |
| "standard cartridge: code must be in $8000-$BFFF" | `.org` set wrongly with `.cartridge "normal"` |
| "bank n: segment ... is not inside the window ..." | segment exceeds the 8 KB window of a bank |
| "ultimax: ROMH code with reset vector at $FFFC missing in the window $E000-$FFFF" | reset vector forgotten |
| "multiple banks (.bank) exist only in the cartridge formats crt/car/rom" | `.bank` in a normal program |

See also: [Directives](help:asm-directives) (`.org`, `.relocate`), [Build and run](help:build). Examples: `examples/c64/cart_demo/cart_demo.asm`, `examples/atari/cart_demo/cart_demo.asm`.
