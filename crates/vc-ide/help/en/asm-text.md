# Assembler: texts and character sets

Computers store letters as numbers. A **character encoding** defines which number belongs to which letter - and it is different on every computer. An "A" is `$41` on a PC, `$01` in C64 screen memory, and the C64 operating system has two different ways to write an "a". For this reason the assembler converts your text into the encoding of the target system when it assembles.

This page belongs to the [assembler manual](help:assembler). Lines of the form `;= 01 02` in the examples show the generated bytes; all examples are tested.

## Which directive do I use?

| I want ... | Use | Result for "A" |
|---|---|---|
| text that is printed with `jsr $ffd2` (CHROUT) | `.petscii "..."` | `$C1` |
| text that I write **directly into screen memory** (`$0400`) | `.screencode "..."` | `$41` |
| text for the Atari operating system (CIO) | `.atascii "..."` | `$41` |
| text unchanged as ASCII (files, logs, foreign formats) | `.byte "..."` or `.text "..."` | `$41` |
| many texts in the **same** encoding | `.encoding "name"` and then `.text "..."` | depends on the encoding |
| text with a **null byte** at the end, a **length byte** in front or **bit 7 set** in the last character | `.textnull`, `.textlen`, `.textshift` | see below |
| an encoding of your own | `.encoding "table.tbl"` | see below |

The earlier names still work and give the same bytes: `.screen` = `.screencode`, `.null` = `.textnull`, `.ptext` = `.textlen`, `.shift` = `.textshift` (table of all old names under [Directives](help:asm-directives)). They stay equivalent; if you write a lot of text, you may keep using the short ones.

All text directives take one or more strings in quotation marks. A quotation mark **inside** the string is not possible (there are no escape sequences like `\"`); write it as a number: `.byte "say ", 34, "hello", 34`. You can mix commas and numbers only with `.byte` (for example `.byte "ABC", 13`), not with `.text` and the others. Characters outside ASCII (umlauts, the sharp s, the euro sign) are stored as UTF-8 in the source file and are written as **several** bytes (the umlaut a gives `$C3 $A4`); if needed, write them as numbers (`{$..}`, see below) or use your own table.

## `.petscii` - for C64 text output

```
.petscii "text", "text", ...
```

**PETSCII** is the character set of the C64 (and VIC-20, C128, Plus/4 and MEGA65) for input and text output through the operating system. The assembler converts like this:

| Source text | PETSCII | Effect on the C64 |
|---|---|---|
| `a`-`z` | `$41`-`$5A` | appears as an **uppercase letter** in the default mode (uppercase/graphics) |
| `A`-`Z` | `$C1`-`$DA` | appears as an uppercase letter in lowercase/uppercase mode; as a graphics character in the default mode |
| digits, punctuation, space | unchanged | |

If your program starts in **default mode** (as the C64 powers on), write text in **lowercase**: `.petscii "hallo"` appears as `HALLO`. If you want uppercase *and* lowercase letters, switch to lowercase/uppercase mode first with `{lower}` (see special characters below).

```asm
.petscii "hallo"
;= 48 41 4c 4c 4f
.petscii "Hi"
;= c8 49
```

## `.screencode` - for screen memory

```
.screencode "text", ...
```

When it prints, the operating system translates PETSCII into **screen codes**, which the video chip knows. If you write into screen memory yourself (`sta $0400,x`), you must store screen codes directly - that is what `.screencode` is for.

| Source text | Screen code |
|---|---|
| `@` | `$00` |
| `a`-`z` | `$01`-`$1A` (uppercase letters in the default mode) |
| `A`-`Z` | `$41`-`$5A` |
| digits, punctuation, space | like ASCII (`$20`-`$3F`) |

On target systems with ANTIC (Atari), `.screencode` converts to the Atari screen code (`A` becomes `$21`, space `$00`).

```asm
.screencode "abc @"
;= 01 02 03 20 00
```

Example - copy text to the screen:

```asm
*= $c000
        ldx #0
loop:   lda meldung,x
        sta $0400,x
        inx
        cpx #meldung_ende - meldung
        bne loop
        rts
meldung:
        .screencode "hallo welt"
meldung_ende:
;=* a2 00 bd 0e c0
```

## `.atascii` - Atari character set

```
.atascii "text", ...
```

**ATASCII** is the encoding of the Atari operating system. It is the same as ASCII, except that the end of line is `$9B` (`{eol}`) instead of `$0A`. There is no `\n` character in the source; write `{eol}`.

```asm
.atascii "Hi{eol}"
;= 48 69 9b
```

## `.text` and `.encoding` - choose the encoding

```
.encoding "name"            ; from here on "name" applies
.encoding "name" {          ; only inside the block
    .text "..."
}
.text "text", ...
```

`.text` stores text in the **current encoding**. Without `.encoding` this is `ascii` (unchanged). It is useful when many strings use the same encoding and you do not want to switch the directive every time; also for tables and blocks.

| Name | Effect |
|---|---|
| `ascii` (default, also `text`) | unchanged |
| `petscii` | like `.petscii` |
| `screen` (also `screencode`) | like `.screencode`; on Atari target systems the Atari screen code |
| `atascii` | like `.atascii` |
| `"file.tbl"` | your own table: exactly 256 bytes; byte *n* of the file is the code for character *n* |

The setting applies until the next switch. With `{ ... }` after the name it applies only in the block; afterwards the previous encoding is active again (labels in the block stay visible).

```asm
.encoding "petscii"
.text "ab"
.encoding "screen"
.text "ab"
.encoding "ascii"
.text "ab"
;= 41 42 01 02 61 62
```

```asm
.encoding "screen" {
    .text "ab"             ; screen code, only here
}
.text "ab"                 ; ascii again
;= 01 02 61 62
```

An unknown name or a table without 256 bytes reports **E208**:

```asm fehler
.encoding "gibts-nicht"
```

```text
error[E208]: .encoding: unknown encoding or file 'gibts-nicht'
```

### Your own tables

A table is a file with **256 bytes**. When assembling, each text character (as a byte `0`-`255`) is replaced by the byte at that position of the file. In this way you can imitate character sets that the assembler does not know, or put characters on your own graphics. The file is searched relative to the source, then in the include folders.

Example with a table `zeichen.tbl` in which every byte is 1 greater (`A` becomes `B`):

```asm
.encoding "zeichen.tbl"
.text "AB"
;= 42 43
```

Non-ASCII characters arrive at the table as UTF-8 bytes. In tables and with `screen` you can also give codes directly as `{$hh}` or `{nnn}` (see below).

## `.textnull`, `.textlen`, `.textshift` - mark the end of text

How does an output routine stop? There are three common ways to mark the end. The directives take **one or more** strings and convert them in the current encoding (`.encoding`); each string gets its own marker.

| Directive | Result for `"AB"` | When |
|---|---|---|
| `.textnull "AB"` | `41 42 00` | the output routine reads up to the null byte (`lda text,x` / `beq fertig`) - the most common form |
| `.textlen "AB"` | `02 41 42` | the length is at the **front**; the routine knows the length in advance, so it can count easily. At most 255 characters, otherwise **E203** |
| `.textshift "AB"` | `41 C2` | bit 7 of the **last** character is set; saves one byte per text, for example in command lists. Empty text is **E203** |

```asm
.encoding "petscii"
.textnull "hi"
.textlen "hi"
.textshift "hi"
;= 48 49 00 02 48 49 48 c9
```

An output routine for a `.textnull` text:

```asm
*= $c000
        ldx #0
loop:   lda text,x
        beq fertig
        jsr $ffd2              ; CHROUT: print a character
        inx
        bne loop
fertig: rts
        .encoding "petscii"
text:   .textnull "{clr}hallo welt{ret}"
;=* a2 00 bd 0e c0 f0 06 20 d2 ff e8 d0 f5 60
```

## Special characters in strings: `{name}`

Control characters like "clear screen" cannot be typed. With `.petscii`, `.atascii`, `.screencode` and with `.text` when an encoding is set (anything except `ascii`), the finished byte is written in **curly braces**:

| Notation | Meaning |
|---|---|
| `{name}` | control character with a name (only for PETSCII and ATASCII), for example `{clr}`, `{down}`, `{rvs on}` |
| `{$hh}` | any code in hexadecimal, for example `{$c1}` - also for graphics characters; with `.screencode` the only form |
| `{nnn}` | any code in decimal, for example `{147}` |
| `{name*3}` | repetition (1 to 255): `{down*3}`, `{$20*40}` |
| `{{` | a single `{` |

- The value in the braces is the **finished byte** and is not converted again.
- Uppercase/lowercase and `_` or `-` instead of spaces do not matter: `{RVS_ON}` = `{rvs on}`.
- The names are in a table for the assembler and BASIC (`data/chars/`). Each language has its **main names** (here `{orange}`, `{ret}`, `{right}`; in BASIC `{orng}`, `{return}`, `{rght}`), and **all names apply in both languages**.
- In the editor the entries appear in their own color, color codes as a color swatch and unknown names with a red wavy underline; hovering shows the code and effect, and after `{` the editor offers the names. A panel that lists all characters is not yet available.
- With `.text` without an encoding (`ascii`), braces are ordinary characters.
- An unknown name, an open brace or a wrong number reports **E208**.

```asm
.petscii "{clr}Hi{down*2}{rvs on}X{rvs off}{ret}{$c1}{147}"
;= 93 c8 49 11 11 12 d8 92 0d c1 93
.petscii "a{{b"
;= 41 7b 42
```

```asm fehler
.petscii "{nix}"
```

```text
error[E208]: unknown special character {nix}
```

With `.screencode` there are no names (the screen code has no control characters), only `{$hh}` and `{nnn}`:

```asm fehler
.screencode "{clr}"
```

```text
error[E208]: {clr}: names are only available with .petscii/.atascii or .encoding "petscii"/"atascii" (only {$hh} and {nnn} here)
```
