# Assembler: Labels, macros, scopes and structures

This page explains how to name places in the program (**labels**), abbreviate recurring pieces of code (**macros**), organize names (**scopes**) and describe data layouts (**structures**). It is part of the [assembler manual](help:assembler). Lines of the form `;= 01 02` show the generated bytes. All examples have been checked with the assembler.

## Labels

A **label** is a name for an address. Instead of `jmp $c012`, you write `jmp start`. The assembler inserts the address, even if you move the code later.

```
name:   lda #1          ; label before an instruction
name:                   ; or alone on a line
```

- A label **must end with a colon**. Without `:`, the assembler treats the first word as an instruction and reports **E205** (`unknown instruction`).
- Names consist of letters (also umlauts), digits and `_`, and do not start with a digit. **Uppercase and lowercase count** for labels (`Start` and `start` are different names). Instructions and directives are not case-sensitive.
- A label must not be defined twice (**E204**). Local labels and scopes are an exception.
- No label may appear before the first `.org` (**E300**).
- A label can also name a number: `name = expression` (see [Constants](help:asm-directives)).

### Local labels: `.name`

Hundreds of loops are called `schleife` or `warten`. So that they do not get in each other's way, start the name with a **period**: `.warten`. A local label belongs to the last **global** label (one without a period) before it. The same `.warten` may appear once under every global label.

```asm
a:      nop
.l:     nop
        jmp .l              ; a.l
b:      nop
.l:     nop
        jmp .l              ; b.l
        jmp a.l             ; from outside: global.local
;= ea ea 4c 01 c0 ea ea 4c 06 c0 4c 01 c0
```

From outside, you address a local label as `global.local` (`a.l`). Local labels are separate for each scope.

### Anonymous labels: `-` and `+`

For short jumps without a name: a single `+` or `-` at the start of a line is a label. In the operand, `-` jumps to the **previous** `-` label, `+` to the **next** `+` label. `--` and `++` skip one, `---` skips two, and so on.

```asm
        ldx #3
-       dex
        bne -               ; back to the "-" above
        beq +               ; forward to the next "+"
        nop
+       rts
;= a2 03 ca d0 fd f0 01 ea 60
```

Anonymous labels count across scopes in source order and do not appear in the symbol table. If a target is missing, the assembler reports **E214**.

```asm fehler
 bne -
```

```text
error[E214]: no matching '-' label before this
```

**Which one should I use?** Use anonymous labels for jumps over two or three lines, local labels (`.name`) for loops and branches inside a routine, and global labels for entry points that are jumped to from elsewhere.

## Macros

A **macro** is a named abbreviation for several lines. At every call, the assembler inserts the text of the macro (like "find and replace") and assembles it. A macro is **not a subroutine**: There is no `jsr` and no `rts`. The code appears anew in the program at every call. This is faster than a subroutine, but it costs memory.

### Define and call

```
.macro name(parameter, parameter, ...)
    ...lines...
.endmacro
```

The parentheses around the parameters are optional (`.macro name a, b` also works). You call the macro like an instruction, with or without parentheses:

```
name value1, value2
name(value1, value2)
```

```asm
.macro wait(n)
        ldx #n
@schleife:
        dex
        bne @schleife
.endmacro

        wait 10             ; ldx #10 / dex / bne
        wait(20)            ; equivalent, with parentheses
;= a2 0a ca d0 fd a2 14 ca d0 fd
```

Rules:

- The macro name is not case-sensitive (`WAIT` = `wait`) and must not be named like an instruction (`nop`, `lda` ... -> **E209**).
- A macro may be called **before** its definition: The assembler collects all macros first.
- A macro definition always applies, even if it is in an `.if` branch that was not chosen.
- A label before the call (`start: wait 10`) gets the address of the first inserted instruction.
- Macros may call other macros, at most 32 levels deep. A call to itself ends with **E211** ("nested too deeply"). A macro cannot define a macro.
- A macro call does **not** open a scope of its own. This way, macros can create global labels on purpose.
- `.macro` without `.endmacro` is **E210**.

### Parameters and call values

The parameters are **text replacement**: Every name that is exactly the same as a parameter is replaced by the argument, except in strings (`"..."`) and comments. The argument can be any text, even a whole operand:

```asm
.macro lade(wert)
        lda wert
.endmacro
        lade #5             ; lda #5      (immediate)
        lade $1234          ; lda $1234   (absolute)
;= a9 05 ad 34 12
```

**Watch out for precedence:** Because of the text replacement, the assembler sees exactly what you type as the argument. `.byte a*2` with the argument `1+2` becomes `.byte 1+2*2`, which is 5 instead of 6. Put parentheses around the parameters when you calculate with them:

```asm
.macro doppelt(a)
        .byte (a) * 2
.endmacro
        doppelt 1 + 2
;= 06
```

**Watch out for parentheses in the call:** At a call, the assembler cuts a leading `(` and a trailing `)` off the argument text (so that `name(a, b)` works). For this reason, you cannot give an argument that **starts** with `(` or **ends** with `)`, such as `lade ($fb),y` or `m 4, (1+2)`. The result is an error message such as **E209** or **E202**. Workarounds: rewrite the argument so that it does not end with a parenthesis (`(1+2)+0`), use a constant (`SUMME = (1+2)`) or move the access mode into the macro.

### Default values

A parameter can have a default value (`name=value`). Parameters with a default value come after the required parameters. At a call, the **right-hand** ones may be left out. A wrong number of arguments is **E209**.

```asm
.macro rahmen(farbe=0, takte=1)
        lda #farbe
        sta $d020
        .repeat takte
        nop
        .endrepeat
.endmacro
        rahmen              ; farbe = 0, takte = 1
        rahmen 5            ; takte = 1
        rahmen 5, 2
;=* a9 00 8d 20 d0 ea
```

```asm fehler
.macro m(a)
        nop
.endmacro
        m 1, 2
```

```text
error[E209]: macro 'M' expects 1 argument(s), got 2
```

### `@label` - labels that are new at every call

If a normal label is in the macro body, it is created again at every call -> **E204**. With an `@` in front, it gets its own name at every call (internally a local label):

```asm
.macro clear(adr, anzahl)
        ldx #anzahl
        lda #0
@loop:  sta adr - 1,x
        dex
        bne @loop
.endmacro
        clear $0400, 8
        clear $0500, 4          ; no conflict: @loop is unique for each call
;=* a2 08 a9 00 9d ff 03 ca d0 fa
```

`@name` applies only inside the macro. Outside, `@x:` is an error. You also get repeatable labels if you put the body in `{ ... }` (scope) - but then they can no longer be reached from outside.

### `.exitmacro` - stop early

Ends the current macro. The assembler does not assemble the rest of the body. It also works from inside `.if` and `.repeat`, but only on the macro in which it is written.

```asm
.macro w(n, reg=1)
        ldx #n
        .if reg == 0
        .exitmacro         ; the macro ends here
        .endif
        nop
.endmacro
        w 1                ; ldx #1 / nop
        w 2, 0             ; only ldx #2
;= a2 01 ea a2 02
```

Marks with `@` after the `.exitmacro` position are then not defined, so do not jump there. `.break` and `.continue` do not work across a macro (**E210** if they are in a macro that is called inside a loop).

### Examples

Increase a 16-bit counter:

```asm
.macro inc16(adr)
        inc adr
        bne @fertig
        inc adr + 1
@fertig:
.endmacro
zaehler = $fb
        inc16 zaehler
;= e6 fb d0 02 e6 fc
```

Macro with a loop inside:

```asm
.macro schleife(n)
        .repeat n, i
        .byte i
        .endrepeat
.endmacro
        schleife 3
;= 00 01 02
```

**Macro, `.function` or `.repeat`?** If you need *code* to reuse, use a macro. If you only need a *number* made from other numbers, use [.function](help:asm-expr). If you want the same block several times in a row, use `.repeat` / `.for` ([Directives](help:asm-directives)). If the code is long and often needed, a subroutine with `jsr` saves more space.

Ready-made macros (16-bit arithmetic, copying memory and more) are in the [system library](help:asm-library).

## Scopes

A **scope** is a namespace of its own: Names in it do not collide with the same names outside. It is opened and closed with curly braces.

```asm
init: {                     ; `init` is a normal label (address of the block) and the name of the scope
        ldx #8
loop:   dex                 ; outside the block, it is called init.loop
        bne loop
        rts
}
main: {
loop:   jsr init            ; main.loop - no conflict with init.loop
        jmp init.loop       ; access from outside: scope name, period, label
}
;= a2 08 ca d0 fd 60 20 00 c0 4c 02 c0
```

- **Visibility:** Inside, all names of the surrounding scopes are visible (the innermost wins). From outside, you reach a symbol only through `scope.name`, and with nesting through `a.b.name`.
- **Anonymous:** `{` without a label opens a scope whose name you cannot address from outside - handy for helper routines and for labels in `.repeat`.
- **`.namespace name {`** does the same, without `name` itself becoming a label (an address) - for example for groups of constants.
- **`.scope` ... `.endscope`** is the word form of `{` ... `}` (`.endscope` also closes a `.namespace`).
- **Local labels** (`.name`) are separate for each scope.
- **Variables** follow the scopes: a `.var` with the same name in the block hides the outer one.
- A scope name must not contain a period. `}` without `{` and a scope that is not closed are **E213**.

```asm
.namespace farbe {
        schwarz = 0
        weiss   = 1
}
        lda #farbe.weiss
;= a9 01
```

### Include with a namespace

`.include "lib/music.inc" as music` puts the content of the file in the scope `music`. From outside, the symbols are called `music.play`, `music.SPEED`. The file itself sees all global names (chip registers, your constants). You can include the same file several times under different names. Macros stay global. There is an example at [.include](help:asm-directives).

## Structures and enumerations

For data with several fields (such as sprite values), it is tedious to count the distances (offsets) yourself. A **structure** gives each field a name and calculates the distances.

```asm
.struct Punkt
    x      .byte
    y      .byte
.endstruct

.struct Sprite
    x      .byte          ; offset 0
    y      .byte          ; 1
    ptr    .word          ; 2
    anim   .byte 4        ; 4: four bytes (the count may be an expression)
    pos    Punkt          ; field of the type of a previously defined structure
    trail  Punkt 3        ; three of them
.endstruct

spieler: .fill Sprite.size, 0        ; space for one instance
        lda spieler + Sprite.y       ; read a field
        ldx #Sprite.size
;= 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 ad 01 c0 a2 10
```

`Sprite.size` is 16 (1 + 1 + 2 + 4 + 2 + 6 bytes). `Sprite.y` is 1.

- Field types: `.byte` (1 byte), `.word` and `.addr` (2), `.dword` and `.long` (4), or a previously defined structure. A count after it multiplies the size.
- These are defined: `NAME.field` (offset), for nested fields also `NAME.pos.x`, and `NAME.size` (total size). The names are normal constants and also apply before the definition.
- A structure does not reserve memory. Use `.fill NAME.size, 0` for that.
- Duplicate field or structure names: **E204**. Unknown field type: **E208**. Missing `.endstruct`: **E210**.

An **enumeration** (`.enum`) assigns consecutive numbers to names:

```asm
.enum Farbe
    schwarz              ; 0
    weiss                ; 1
    rot = 5
    gruen, blau          ; 6, 7  (also several on one line)
.endenum
        lda #Farbe.rot
;= a9 05
```
