# MEGA65 (45GS02)

Target `mega65`: PRG from `$2001` with `.basicstub`, chips `vic4` (VIC-III/IV), `dmagic`, `mega65`.

## Instruction set (65CE02 + MEGA65)
- New registers **Z** and **B**: `ldz`, `cpz`, `inz`, `dez`, `phz`, `plz`, `taz`, `tza`, `tab`, `tba`; stack: `tsy`, `tys`.
- Pointers: `lda ($nn),z`, `lda ($nn,sp),y` (stack-relative).
- 16 bit: `phw #$1234`, `phw $1234`, `inw`, `dew`, `asw`, `row`.
- Jumps: `bsr`, `jsr ($nnnn,x)`, `jmp ($nnnn,x)`, `rts #n`, **long branches** `lbne`, `lbeq`, `lbra` ... (16 bit); short `bne` stay 8 bit.
- Bits: `bbr0..7`, `bbs0..7` (`bbr3 $10,target`), `rmb`, `smb`, `trb`, `tsb`, `stz`.
- `neg`, `asr`, `map`, `eom` (`nop` is an alias), `cle`, `see`.

## 32-bit
- **Pointers:** `lda [$nn],z` - four zero-page bytes from `$nn` are a 32-bit address.
- **Q register** (A, X, Y, Z together): `ldq`, `stq`, `adcq`, `sbcq`, `andq`, `orq`, `eorq`, `cpq`, `bitq`, `aslq`, `lsrq`, `rolq`, `rorq`, `asrq`, `inq`, `deq`, `negq` (`aslq q`).

## Unlocking the VIC-IV
The **VIC-IV** is the extended graphics chip of the MEGA65. It contains the VIC-II of the C64 and adds more registers (text up to 640 pixels wide, color characters with 256 colors, 32-bit pointers to screen memory, wide sprites). So that the MEGA65 behaves like a C64 after power-on, these **extended registers are locked at first**. Pure VIC-II registers such as `vic2.border` always work; a write to a locked register (all with the name `VIC4_...` or in the chip group `vic4`) has no effect.

You **unlock** them with the key register `vic4.key` (address `$D02F`): first write `$47`, then `$53` into it, in this order. You need it once at the start of the program, before you use an extended register. Because the assembler knows only one instruction per line (no `:` as a separator), it takes four lines:

```asm target=mega65
        lda #$47
        sta vic4.key
        lda #$53
        sta vic4.key
;= a9 47 8d 2f d0 a9 53 8d 2f d0
```

It is shorter with the macro `mega65_enable_vic4` of the system library ([System library](help:asm-library)). It creates the same four instructions and changes only the accumulator:

```asm target=mega65
#include <mega65/gs4502.asm>
        mega65_enable_vic4
;= a9 47 8d 2f d0 a9 53 8d 2f d0
```

Which notation? The macro form is shorter and says what is meant; the four lines need no library and show what happens. Both give exactly the same bytes. The project template and the example projects (`examples/mega65`) use the macro; the generated bytes are the same as with the four lines.

## Running and debugging
As a target in the header (chip "MEGA65 · ... ▾"), the program loads into memory through the UART monitor and sets the PC to the entry point. Connection: `xemu` (starts the Xemu emulator, environment variable `VC_XEMU_SD` = folder with `MEGA65.ROM`; otherwise the ROM directory, see "ROM files"), `unix:/path/socket` (running Xemu with `-uartmon`) or `/dev/cu.usbserial-...` (real hardware). Possible: registers, memory, pause/continue, single step, one breakpoint.

## BASIC 65
Dialect `basic65` (load address `$2001`). BASIC source (`.bas`) is translated to BASIC 65 tokens; the result is byte-identical to `petcat -w65`. Commands such as `border`, `background`, `foreground`, `vsync`, `play`, `tempo`, `envelope` are known to the keyword list (F1 on the word).

## Four SIDs, VIC-IV
- **C64 media:** The MEGA65 runs in C64 mode and contains the VIC-II and SID, so the C64 media profiles (sprites, character sets, screens, tiles, `c64.sid.song`) also apply in MEGA65 projects, and `.include "music/tune.vcsong"` with a C64 song builds without error E219. MEGA65 profiles of its own (below) exist in addition.
- **Music:** the profile `mega65.sid4.song` has 12 voices (4 x SID at `$D400/$D420/$D440/$D460`). The tracker exports as for the C64; the play routine is in `examples/mega65/music_demo/lib/music.inc`.
- **PLAY tracker:** profile `mega65.play` - 6 voices, export as a BASIC program with `VOL`, `TEMPO`, `ENVELOPE` and `PLAY` strings (see the topic "PLAY tracker").
- **Palette:** profile `mega65.palette` (256 colors, 8 bits per channel); export to the register form of `$D100/$D200/$D300` (nibbles swapped). Example: `examples/mega65/pal_demo/pal_demo.asm`.
- **Full-color characters (FCM):** profile `mega65.char.fcm`, 8x8 pixels with 2 hex digits (palette index 0-255) per pixel, 64 bytes per character.

## F5 and disk image
F5 starts `xmega65` and loads the program through the monitor. Choose the format: `vcc asm ... --format d81`.

Note: The hardware connection is not tested on a real device; BASIC 65 programs and autoload were not run in Xemu (without configuration, Xemu stays in the setup screen).

## Setting up Xemu
- **ROM:** Put a MEGA65 ROM file (128 KB, 131072 bytes; original or the open-source open ROMs) into the ROM folder: Settings > **ROMs** (**Choose ROM file or zip ...** or drop it on the window), the assistant (Help > Setup assistant: ROMs only ...) or `vcc roms import <file>`; the name does not matter, the file is recognized by its content. The old location `~/.config/vintagecoder/mega65/MEGA65.ROM`, the folder under Settings > **Targets and hardware** and `VC_XEMU_SD` still apply. Xemu is started with `-rom` on the file that was found; if it is missing, the message names the places that were searched. See the help "ROM files".
- **Program:** `xmega65` is searched in `/opt/homebrew/bin`, `/usr/local/bin` and `/Applications/xmega65.app/Contents/MacOS` (otherwise set `VC_XEMU`).
- **Start:** F5 and F6 start Xemu, load the program into memory through the monitor and begin at the `SYS` target of the BASIC starter (F6 then stops at the breakpoint). The start takes about 15 seconds. Autoload from disk (`RUN"*"`) fails with the open ROMs, so it is not used.
- **Breakpoints:** Xemu stops at the breakpoint only *after* the instruction; the PC is then at the following instruction. There is one breakpoint per session.
- **Self-tests without a window:** `VC_XEMU_ARGS="-headless"`.
